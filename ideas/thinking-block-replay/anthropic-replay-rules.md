# What Anthropic actually documents about replaying thinking blocks

Sourcing for fact 1 in the idea file. Fetched 2026-08-29 from
`platform.claude.com/docs/en/build-with-claude/thinking` (and
`/thinking-troubleshooting`, `/thinking-tool-workflows`).

## The switch rule — silently ignored, not rejected

§*Thinking block preservation by model* → *Switching models
mid-conversation*:

> When you switch between any two models, for example after a classifier
> refusal fallback, strip `thinking` and `redacted_thinking` blocks from
> prior assistant turns. Thinking blocks are tied to the model that
> produced them. **Other models silently ignore them rather than rejecting
> the request, but ignored blocks still add input tokens.**

So the vendor's prescribed repair *is* "drop the whole block" — but the
reason is cost, not validity. This is the sentence that falsifies
`D_history_load_repairs`' "replaying one after a switch is a 400".

## The 400 that does exist — modified blocks, latest message only

§*A 400 error says thinking blocks cannot be modified* gives the server
text:

```text
`thinking` or `redacted_thinking` blocks in the latest assistant message
cannot be modified
```

> This error happens when the assistant message you send back differs
> from the one the API returned, most often because your code filters
> content blocks by type and drops `redacted_thinking` blocks, or
> rebuilds the assistant message instead of echoing it.

And from §*Preserving thinking blocks*:

> Within the latest assistant message, the sequence of consecutive
> `thinking` blocks must match what the model generated in the original
> request: you can't rearrange, edit, or partially drop them. This
> includes `redacted_thinking` blocks.

Note the scoping to *the latest assistant message* — it is not a
whole-history rule. Everything in a loaded history is a completed prior
turn.

## The three-way rule

§*Preserving thinking blocks*:

> * **Required:** within a tool-use turn, pass thinking blocks back.
> * **Recommended:** across turns, pass everything back.
> * **Allowed:** outside tool use, omit prior turns' thinking.

Reinforced in §*Thinking encryption*:

> It is only strictly necessary to send back thinking blocks when using
> tools with thinking. Otherwise you can omit thinking blocks from
> previous turns.

This is what settles the old open question "is dropping legal for a prior
assistant turn carrying `tool_calls`?" — yes, for a *completed* turn.

## What a signature is (not what the name suggests)

§*Thinking encryption*:

> **Full thinking content is encrypted and returned in the `signature`
> field** on each thinking block. The API uses the signature to verify
> that thinking blocks were generated by Claude when you pass them back.

So the signature is not a checksum over the text — it *is* the reasoning,
encrypted, plus an attestation. The `thinking` text is a lossy
human-facing summary; the raw chain of thought is never returned as text.
On Opus 5 / 4.8 / 4.7, Sonnet 5 and Fable 5, `display` defaults to
`"omitted"`, so the text is an **empty string with only the signature
populated**.

Also from that section: signatures are opaque ("don't interpret or
parse it") and portable — "`signature` values are compatible across
platforms (the Claude API, Amazon Bedrock, and Google Cloud). Values
generated on one platform work on another." That last sentence is what
demotes option 3.

`redacted_thinking` is the same idea with the readable half gone:
"encrypted thinking content in a `data` field, with no readable text",
returned when reasoning is safety-redacted.

## Preservation is per-model, and automatic

§*Thinking block preservation by model*: keep-all on Opus 4.5+ / Sonnet
4.6+ / Fable 5 / Mythos; last-turn-only on earlier models and all Haiku
through 4.5, where "the API strips them automatically. You don't need to
remove them yourself."

## Graceful degradation

§*Thinking with tool use* — relevant to the sibling note more than this
one, but it is why nothing here fails loudly:

> If you toggle thinking mid-turn […] the API doesn't error. Instead, it
> silently disables thinking for that request. To preserve model quality,
> the API may strip thinking blocks that would create an invalid turn
> structure, or disable thinking when the conversation history is
> incompatible with thinking being enabled.
