# Changelog

All notable changes to pikuri, newest first. Versioning is semver as
documented in `pikuri-core/lib/pikuri/version.rb`. The `0.0.4`–`0.0.7`
sections were reconstructed from git history in August 2026, after those
releases had shipped without one.

**An entry is one sentence.** Lead with `Add` / `Fix` / `**Breaking:**`,
name the symbol, say what changed — roughly 40 words, plus an optional
`D_<slug>` or book pointer. The rationale lives in `design/decisions.md`,
the yardoc and the book; an entry links rather than restates. A breaking
entry gets one second sentence, for the migration.

**A release is a flat list**, grouped `Add`, then `Fix`, then
`**Breaking:**`, under an optional ≤3-sentence preamble where the release
has a theme. A shipped section is closed — new work goes under
`[Unreleased]`, and a version heading is never left unwritten while tags
march on.

## [Unreleased]

- Fix `Pikuri::Workspace::Filesystem` reading a model's `~/.bashrc` as a folder named `~` inside the workspace; a leading `~` now expands to the home folder, so the path is refused as outside the workspace (or reached, when it is inside).
- `thunderbird_mail_read` ends a body that reached Thunderbird's 20 KB index cap with a note that the message may continue, instead of stopping mid-sentence without a word; the full text stays in Thunderbird.
- `thunderbird_mail_attachment_read` answers a PNG, JPEG, GIF or WebP attachment as the picture itself, for a vision model to see; a text-only model gets a note instead (`D_refuse_unsupported_attachments`).
- **Breaking:** the 5 MB image cap moved from `Pikuri::Workspace::Read::MAX_IMAGE_BYTES` to `Pikuri::Attachment::MAX_IMAGE_BYTES`, so every gem attaching an image shares it; rename the constant where you read it.
- Fix `Pikuri::Attachment#to_ruby_llm` letting ruby_llm guess the type from the file name; it now passes `mime` through, so the provider is told the type pikuri checked.
- Fix `Pikuri::FileType.detect_mime` raising `Encoding::CompatibilityError` on a UTF-8 String holding non-ASCII; it now sniffs a binary copy of the leading bytes.
- `thunderbird_mail_attachment_read` now reads a forwarded email (`message/rfc822`) as its sender, recipients, date, attachment list and text (`Pikuri::Thunderbird::ForwardedMail`), and `thunderbird_mail_read` lists one as `forwarded email`, noting its text may already be in the body.
- Fix `thunderbird_mail_read` failing the turn on a body over 40 KB whose cut split a multi-byte character; the torn tail is now dropped.

- **Breaking:** `Agent::History` is in-memory only: `#to_json`, `#to_h`, `#save`, `.parse`, `.from_h`, `.load`, `History::Error`, `#version` and `Attachment#stored_name` are gone, since storing a conversation is the host's job and moves to pikuri-workshop; hand `agent.export_history` straight to `Agent.new(history:)`.
- **Breaking:** `Agent.new` takes no `interloper:`; every agent builds its own `Control::Interloper`, reached as `Agent#interloper`, so a queued mid-turn message can't leak into the next conversation's agent. Read `agent.interloper` (or `c.interloper` inside the block) where you held your own.
- **Breaking:** an `Agent` is one conversation: `clear_conversation`, `load_history!`, `Extension#on_conversation_reset`, `Event::Reset` and `Workspace#clear_reads` are gone, and a conversation resumes through `Agent.new(history:)` (`D_agent_is_one_conversation`). To clear or switch, close the agent and build a new one with fresh extension instances.
- **Breaking:** an extension has one setup hook: `Extension#bind` and `Agent::ExtensionContext` are gone, the `Configurator` carries `emit_event`, `add_raw_tool`, `sub_agent_listeners`, `agent` and `history` and stays usable after construction, its `transport` / `id` / `streaming` / `cancellable` / `around_request` / `interloper` / `system_prompt_base` readers moved to `c.agent`, and `on_user_message` drops its `ctx` argument (`D_one_phase_extensions`); move a `bind` body into `configure`, keeping `c` where you kept `ctx`.
- **Breaking:** `Configurator#add_extension` raises `ArgumentError` on an extension instance already added to an agent, even a closed one; build a fresh one for every `Agent.new`.
- Add `pikuri-workspace/bin/pikuri-files`, a demo agent working in one folder with the six file tools, every change shown as a diff before it lands; walk-through in `book/touching-files.md`.
- **Breaking:** every demo binary's default model is now `ornith-ai/Ornith-1.5-35B-A3B-GGUF:Q4_K_M`, the same size as the Qwen3.6-35B-A3B it replaces and newer; an `llm_model:` line in `~/.pikuri-examples-config.yaml` still overrides it.
- **Breaking:** a host now calls `Agent::Control::Cancellable#reset!` where it starts a turn, on its own thread, before handing the turn to a worker. Without it, every turn after a cancel ends at once.
- Fix a cancel sent before the turn's thread reaches `Agent#run_loop`, or while a sub-agent is being built, being lost: `run_loop` no longer resets the `Cancellable`, and checks it before its first request.
- Fix `bin/pikuri-minions` crashing at boot on the removed `Pikuri::Tool::WEB_SEARCH`; it builds its search tool from the config, as `pikuri-chat` does.
- Fix the trifecta detector grading a node loud when one egress tool skipped review and another reached the attacker: loud now needs one tool that is both (`Pikuri::Tool::TrifectaLegs#egress_open`), and such a node's map shows both shapes, `[:egress_reviewed, :egress_vouched]` (`D_egress_axis_shape`).
- Fix the compose guard's novelty warning never firing on a reply to a new sender: only a domain you have *sent* mail to counts as known (`Gloda::Contacts#domains_sent_to`, renamed from `domains_seen`), since an attacker earned "seen" by writing first.
- Fix the Thunderbird calendar tools missing an event added while Thunderbird runs: `Pikuri::Thunderbird::DatabaseSnapshot` now copies a store's `-wal` too and notices a commit that only reached it.
- `read` and `edit` now name the workspace root when a file isn't found — `file not found: xyz/spec.txt (relative paths resolve against /home/alice/Notes)` — so a model holding a path relative to another folder sees why it missed.
- **Breaking:** `rag_find` is renamed `rag_search_keywords` (class `Pikuri::Rag::Tools::SearchKeywords`), because *search* and *find* are synonyms and the pair said nothing about how the two differ (`D_rag_gem`); a prompt or transcript naming `rag_find` needs the new name.
- `rag_search_keywords` answers an empty AND with each word's own document count — `"solar" (3 documents), "array" (2 documents), "wattage" (0 documents)` — so the model retries without the word that emptied the set.
- **Breaking:** the vector-store supervisors run Qdrant and Chroma with `podman` when it is on `PATH`, else `docker`, so a rootless setup comes out of the box; `Pikuri::VectorDb::Server::DockerContainer` is renamed `Server::Container`, and the image pins are now fully qualified (`docker.io/…`).
- Add `exclude:` to `Pikuri::VectorDb::Indexer` and both `VectorDb::Extension` and `Rag::Extension`, which keeps whole folders (a library of books, say) out of the walk and the watcher, and `--exclude` on `bin/pikuri-secretary`.
- `Pikuri::VectorDb::Watcher` now logs a line before its boot scan, numbers each swept file `[i/total]`, and logs the sweep's end with its duration, and the `Indexer` announces a file of 20 or more chunks before embedding it, so a long index is no longer silent.
- **Breaking:** `bin/pikuri-secretary` keeps its index in Qdrant by default, since a real `~/Documents` takes hours to embed; `--in-memory` replaces `--qdrant`.
- Add `bin/pikuri-secretary`, a CLI personal assistant over your documents, notes, mail, calendar and the web, holding all three trifecta legs and weakening each: snippets-only confirmed search, Thunderbird hand-offs, and note writes confined to one folder and confirmed with a diff.
- Add `Pikuri::Web::Search.build(confirmer:)`, which shows the human each query, editable, before it leaves, grading the leg `:human_reviewed`, and `snippets_only:`, which tells the model the snippets are the whole answer; `pikuri-web` now depends on `pikuri-workspace` for the `Confirmer` seam.
- **Breaking:** `pikuri-code`, `pikuri-os`, `pikuri-lsp`, `pikuri-mcp`, `pikuri-skills`, `pikuri-tasks`, `pikuri-memory` and `pikuri-extractors` moved to [pikuri-workshop](https://github.com/mvysny/pikuri-workshop), with their book chapters, because each needs a cage or grows by features (`pikuri-workshop:D_separate_repo`). A host that wires one takes it from that repo instead.
- **Breaking:** the `pikuri` metagem is gone, because installing every gem goes against wiring only what the job needs (`D_no_metagem`); replace `gem 'pikuri'` with a `gem` line for each pikuri-* gem you wire, and `require 'pikuri'` with their requires.
- **Breaking:** the HTML → Markdown extractor left pikuri-core for pikuri-web as `Pikuri::Web::HTML`, registered by `require 'pikuri-web'`, and takes nokogiri, ruby-readability and reverse_markdown with it; without pikuri-web a `text/html` body reads as raw markup. A host that wants rendered HTML outside the web tools (a mail attachment) requires pikuri-web.
- **Breaking:** `Pikuri::Agent::Listener::RateLimited` is gone — nothing in pikuri wired it, and pacing a renderer's repaints is the renderer's business. A host that coalesced streaming deltas with it keeps a copy of the class in its own code.
- **Breaking:** `pikuri-assistant` is gone, and the book's stub assistant chapter with it; the coda now points at the apps built on pikuri (pikuri-tui, pikuri-web, Puri), where the assistant's shape is being worked out. Wire `bin/pikuri-code`'s MCP registry, or one of those apps, instead.
- **Breaking:** `pikuri-code` and `pikuri-os` no longer depend on the gems only their demo binaries wire: `pikuri-code` drops `pikuri-tasks` and `pikuri-web`, `pikuri-os` drops `pikuri-pdf`, `pikuri-subagents` and `pikuri-web`. A host that relied on one arriving transitively adds it to its own `Gemfile`.

- **Breaking:** the web tools left pikuri-core for the new `pikuri-web` gem, renamed into its namespace — `Pikuri::Web::Search` (was `Tool::WebSearch` plus `Tool::Search::*`), `Web::SCRAPE`, `Web::FETCH`, `Web::READ_CACHED`, `Web::Scraper`, `Web::UrlCache` — so an agent that wires none never loads them. Add `gem 'pikuri-web'` and `require 'pikuri-web'`, then rename the constants; see `D_read_what_you_run`.
- `Pikuri::Testing` scripts now drive a `streaming: true` agent with every verb, a tool call streamed in fragments as a server sends it; `Script#responses` holds `Testing::Completion`s.
- Add `Pikuri::Tool::WEB_READ_CACHED` and `WebSearch.build(page_text: true)`: Brave (via LLM Context) and Exa bring back each result's page text from their own index in the same request, `web_search` prints a handle beside each readable row, and `web_read_cached` returns that text by handle without any network request — a search-only agent whose one egress leg stays the vouched search.
- **Breaking:** `web_search`'s query caches now hold result rows as JSON, not rendered Markdown, and its summary counts rows. Clear `~/.cache/pikuri/url_cache/web_search/` once, or wait 2 h for old entries to expire.
- **Breaking:** `Pikuri::UrlCache` is now a namespace holding `UrlCache::OnDisk` (the old class, plus `read` / `write`) and the new `UrlCache::InMemory`, and `web_search` keeps Brave and Exa results in memory only — their API terms forbid storing them — via each provider's `disk_cacheable?`. Replace `UrlCache.new` with `UrlCache::OnDisk.new`, and `Engines.new(cache:)` with `disk_cache:` / `memory_cache:`.
- **Breaking:** `Pikuri::Workspace::Confirmer#ask` answers `Approved`, a textless `Rejected` (the model is told to stop) or the new `Redirected(message:)` (the human's typed words, handed to the model as guidance), and `Confirmer::Terminal` asks `[y] approve  [n] reject  [r] redirect`; a custom confirmer returns `Rejected.new` for a plain no and `Redirected` wherever it used to send a reason, and may raise `Agent::Control::Cancellable::Cancelled` from a parked `#ask` to cancel the turn. See `D_bare_rejected`.
- Add `Pikuri::Agent::ChatTransport#with_detected_modalities`, which reads a llama.cpp router's `/v1/models` (or a single server's `/props`) without loading the model, so `Agent#modalities` is known before the first turn; `Agent#modalities` now also follows a model switch at once. See `D_refuse_unsupported_attachments`.
- **Breaking:** `Pikuri::Agent::Extension#on_user_message` takes a third argument, the turn's `Pikuri::Attachment`s, and now fires on an attachment-only turn too (with `""`), so `pikuri-memory` records a note naming each attached file. Add the parameter to your override.
- Add `attachments:` to `Pikuri::Agent::Control::Interloper#inject_user_message`, so a host can show the model an image mid-loop; one the model can't see is withheld with a note in the text rather than ending the running turn.
- Fix `Pikuri::Tool::Search::Exa` letting Exa fetch an uncached result page live during a search, a channel through which an attacker who owns indexed pages could learn which of them a query matched; it now sends `maxAgeHours: -1`, cache only.
- Fix a mid-loop user message drained from the `Interloper` getting a fresh `Agent::History` id on every `export_history`.
- Add `Pikuri::Agent#modalities`, read from llama.cpp's `/props` (or stated as `ChatTransport#modalities`): `run_loop` raises `Pikuri::Agent::UnsupportedAttachmentError` for an image a text-only model can't see, and a tool's such image becomes a note, instead of an HTTP 500 that poisons the history; see `D_refuse_unsupported_attachments`.
- Fix `SubAgentTool` building its child's transport once at bind time, which inherited only a host-stated cap and ignored a later model switch; it now bakes in the parent's resolved cap and modalities at each spawn.
- Add `@path` to `pikuri-chat`: a `@~/shot.png` token in a typed line attaches that image (PNG, JPEG, GIF or WebP, up to 5 MB) to the turn; see `book/chat.md`.
- Add `attachments:` to `Pikuri::Agent#run_loop`, so a host can show the model an image with the user's message (or alone), and `Pikuri::Agent::Event::UserTurn#attachments`, which carries them to listeners.

A tool returning an attachment builds `Pikuri::Attachment.new(mime:, filename:, bytes:)`.
- Fix `rag_search` burying a leg's rank-1 hit under chunks both legs listed deep down — `Pikuri::Rag::Tools::Search` now fuses each leg's top `LEG_K` (10) with `RRF_K` 5 instead of 50 with 60, and the reranker scores at most 20 candidates; see `design/decisions.md` `D_rrf_tuning`.
- **Breaking:** `Pikuri::Rag::Tools::Search::CANDIDATE_K` is gone, replaced by `LEG_K`. Code that read it for the per-leg depth reads `LEG_K`, or `Pikuri::VectorDb::Tools::Search::CANDIDATE_K` for vectordb's.
